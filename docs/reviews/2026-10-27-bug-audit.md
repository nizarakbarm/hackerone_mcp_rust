## Fixed in this session

1. **No HTTP timeout** (`hackerone-api`) — a hung HackerOne request blocked the tool call forever.
   Now `connect_timeout(10s)` + per-request `timeout(30s)` (ADR-0009). Red: a wiremock route that
   outlives a 50 ms test timeout now yields `Error::Transport`.
2. **Unvalidated paths** (`Client::request`) — `format!("{base}{path}")` accepted anything the
   caller passed. Now rejects a non-`/`-prefixed path or a `..` segment with `Validation` before any
   request, so a future caller cannot inject one. Tests cover `../admin`, `/reports/../admin`, `..`.
3. **Harness leak check was top-level only** — nested `properties.filter.properties.program` passed.
   Now walks the whole schema (objects and array `items`) and names the dotted path.
4. **Harness could hang** — blocking `read_line` on the child. Now reader thread + `recv_timeout`
   (`--timeout-seconds`, default 30), kills the child and exits non-zero; test proves a silent child
   fails in <2 s with a 1 s timeout.
5. **Tautological enum test** — `schema.enum == json!(REPORT_STATES)` compares a constant to itself.
   Replaced with golden literals for states, severities, sort fields, sort orders.
6. **Weak capabilities assertion** — `capabilities.tools.is_object()` admitted `{}`. Now asserts
   `capabilities == {"tools": {}}` exactly.

## Fixed earlier, found by the same audit work (live testing)

7. `search_programs` could not resume a truncated scan (`next_page` was output-only) and could report
   a program twice when the directory shifted between page requests. Added `start_page`, dedupe by
   id. Context: the directory holds ~595 programs, so the 5×25 default budget sees ~21% of it.

## Accepted risks (documented, not fixed)

- **rmcp 5 s drain window** (`QuitReason::Closed`): a tool still running when the client closes stdin
  is cancelled and its result dropped. Hardcoded in rmcp 3.7 and 3.8; no API to change it. Mitigated
  by the per-request timeout and documented in ADR-0009 and the README contract that clients keep
  stdin open until the response arrives. Observed live as
  `WARN rmcp::service: timed out draining in-flight responses`.
- **`constant_time_eq` early-returns on length mismatch**, so the bearer token's *length* is
  observable by timing. Length is not secret-bearing for an operator-chosen token; recorded rather
  than hashed-compared for no practical gain.
- **Redirect credential handling** depends on reqwest stripping `Authorization` on cross-host
  redirects (verified in its `redirect.rs`, not our code). A `base_url` pointed at a hostile host
  inherits that dependency's guarantees.
