# Triage

Move issues on the project tracker through a small state machine of triage roles. Every comment or issue posted during triage **must** start with:

> *This was generated by AI during triage.*

If the repo treats external pull requests as a request surface (see `docs/agents/issue-tracker.md`), triage covers them too: **a PR is an issue with attached code** — same roles, states, and machine. Resolve a bare `#42` per the tracker config.

## Reference docs

- `skill://triage/references/roles.md` + `docs/agents/triage-labels.md`: roles, PR readings, transitions, label strings
- `skill://triage/references/checks.md`, `outcomes.md`, `attention.md`: codebase checks, per-outcome actions, the attention buckets
- `skill://triage/AGENT-BRIEF.md`, `OUT-OF-SCOPE.md`: durable briefs, the `.out-of-scope/` knowledge base

## Invocation

The maintainer invokes `/skill:triage` and describes what they want in natural language; interpret and act — "show me what needs my attention", "look at #42", "move #42 to ready-for-agent", "what's ready for agents?".

## Show what needs attention

Query the tracker and present the three buckets defined in `skill://triage/references/attention.md`, oldest first. Show counts and a one-line summary per item, then let them pick.

## Triage a specific issue or PR

1. **Gather context.** Read the full issue or PR (body, comments, labels, author, dates; PR: the diff too) and any prior triage notes, so you don't re-ask resolved questions. Explore the codebase with the project's glossary, respecting ADRs, then run the checks in `skill://triage/references/checks.md`: **redundancy** and **prior rejection**.

2. **Recommend.** Give them your category and state recommendation with reasoning, plus a codebase summary relevant to the request. Wait for direction.

3. **Verify the claim** before any grilling: for a bug, reproduce the reporter's steps; for a PR, check out the diff and run the relevant tests or commands. Report confirmed (with code path), failed, or insufficient detail — a strong `needs-info` signal. Confirmation makes a much stronger agent brief.

4. **Grill (if needed).** Read `skill://grilling` and `skill://domain-modeling`, then grill it into shape a round at a time, sharpening domain terms and updating `GLOSSARY.md`/ADRs inline as decisions land.

5. **Apply the outcome.** One entry per role in `skill://triage/references/outcomes.md`, naming what gets posted or closed.

## Quick state override

If the maintainer says "move #42 to ready-for-agent", trust them and apply the role directly. Confirm the change, then act — no grilling. No grilling session? Use `ask` for whether to write an agent brief.

## Resuming a session

If prior triage notes exist, read them, check whether the reporter answered outstanding questions, and present the updated picture before continuing. Don't re-ask resolved questions. Post the output in full to the tracker; reply with a ≤3-line summary.
